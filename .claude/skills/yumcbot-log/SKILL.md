# YUMCBOT 활동 로그 조회

`activity_logs` / `score_logs` / `event_sessions` / `rounds` 를 읽어 정형화된 표로 출력한다.
**출력 포맷은 스크립트가 전부 만든다. 직접 표를 다시 그리지 말고 스크립트 출력을 그대로 보여준다.**

## 실행

저장소 루트에서:

```bash
python .claude/skills/yumcbot-log/scripts/yumcbot_log.py <명령> [인자]
```

Windows PowerShell (venv를 쓰면 더 확실하다):

```powershell
.\.venv\Scripts\python.exe .claude\skills\yumcbot-log\scripts\yumcbot_log.py <명령> [인자]
```

표준 라이브러리만 쓰므로 venv 없이 시스템 `python`으로도 돈다.
한글이 깨지면 `$env:PYTHONIOENCODING='utf-8'` 을 먼저 준다.

DB 경로는 자동 탐지한다: `--db` → `$YUMCBOT_LOG_DB` → 저장소 `data/event_game.sqlite3` →
`~/Downloads/*.sqlite3`(최신순). 못 찾으면 스크립트가 뭘 하면 되는지 안내하고 종료하므로,
그 안내를 그대로 사용자에게 전달하면 된다. DB는 **읽기 전용**으로만 연다 — 봇이 돌고 있어도 안전하다.

## 명령

| 명령 | 용도 |
| --- | --- |
| `summary <이름\|ID>` | **기본.** 유저 활동 요약 (기간·이벤트·룰렛 전적·선택 변경·점수·일자별) |
| `detail <이름\|ID> [--date YYYY-MM-DD] [--raw]` | 상세 로그. 날짜 없으면 전체 기간 |
| `scores <이름\|ID> [--date YYYY-MM-DD]` | 점수 변동만 |
| `event <이벤트ID>` | 이벤트 하나의 전체 타임라인 (모든 유저) |
| `events [--user <이름\|ID>]` | 이벤트 목록 |
| `whois <이름>` | 이름으로 유저 검색 |

## 요청 → 명령 매핑

| 사용자가 이렇게 말하면 | 이렇게 실행 |
| --- | --- |
| `/yumcbot-log 도연`, "도연 로그" | `summary 도연` |
| "이날 로그 뽑아줘", "7월 21일 것" | `detail <ID> --date 2026-07-21` |
| "전부 다 보여줘", "상세하게" | `detail <ID>` (날짜 없이) |
| "점수 변동 보여줘" | `scores <ID>` |
| "이날의 이벤트 로그" | `event <이벤트ID>` — ID를 모르면 먼저 `events --user <ID>` |
| "누구누구 있어?" | `whois <이름>` |
| "원본도 보고 싶어" | `detail <ID> --raw` |

**요약 vs 상세**: 처음 유저 이름만 받으면 `summary`. 그 뒤 구체적인 요청("이날", "점수", "이벤트")이
오면 `detail`/`scores`/`event`로 **최대한 다 뽑는다** — 이때는 요약하지 말고 전체를 보여준다.

## 동작 규칙

1. **스크립트 출력을 그대로 전달한다.** 표를 다시 그리거나 요약해서 줄이지 않는다.
   사용자가 이 스킬을 쓰는 이유가 "매번 로그를 손으로 뜯어보는 시간을 줄이는 것"이다.
2. **동명이인**: 후보가 여러 명이면 스크립트가 후보 표를 내고 멈춘다. 그 표를 보여주고
   어느 ID인지 물어본 뒤 그 ID로 다시 실행한다.
3. **후속 요청은 ID를 재사용한다.** 한 번 유저를 특정했으면 이후 명령엔 이름 대신 ID를 쓴다.
4. **스크립트 출력 끝의 "더 보기" 안내**를 사용자에게 같이 보여주면, 다음에 뭘 물어볼 수 있는지 알 수 있다.
5. 출력 뒤 덧붙일 말이 있다면 **표 아래에 짧게**. 표 위에 서론을 길게 쓰지 않는다.

## 읽는 법 (사용자에게 설명이 필요할 때)

- `E1/R2` = 이벤트 1의 라운드 2. `범위` 칸에 나온다.
- `상대` 칸 = 매칭 상대, 룰렛 상대 등. 남이 나를 지목한 것도 내 로그에 잡힌다
  (조회가 `actor` 또는 `target` 양쪽을 본다).
- **`A → B ⟵ 변경`** = 선택을 바꾼 기록. `votes` 테이블에는 최종값만 남아서
  이 로그가 아니면 "흔들렸다"는 사실 자체가 사라진다. 심리전 분석의 핵심 데이터다.
- 점수는 `activity_logs`가 아니라 `score_logs`에 개별 델타로 남는다.
  `summary`/`detail`은 둘을 같이 보여준다.

## 주의

- 스키마 v5 미만 DB에는 `activity_logs`가 없다. 스크립트가 그 사실을 알려주고 종료한다.
- 운영 DB는 서버(`/var/lib/yumcbot/data/event_game.sqlite3`)에 있다. 로컬에서 보려면
  디스코드 `/데이터백업`으로 받은 파일을 쓰거나 `$YUMCBOT_LOG_DB`로 경로를 지정한다.
